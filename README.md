# Forged

Source for [Forged](https://forged.damienmurphy.net/), Damien Murphy's
personal blog.

Forged publishes practical, reflective field notes connecting software
engineering with personal systems, resilience, work, organisations, learning,
and life. It is based on AstroPaper and deployed as a static site to GitHub
Pages.

## Tech Stack

- [Astro 6](https://astro.build/) with TypeScript
- [AstroPaper](https://github.com/satnaing/astro-paper) theme foundation
- [Tailwind CSS v4](https://tailwindcss.com/)
- Pagefind static search
- Markdown and MDX content collections
- Dynamic Open Graph image generation
- GitHub Pages hosting

Node.js 22.12 or newer and pnpm are required. CI and deployment currently use
Node.js 24.

## Project Structure

```text
astro-paper.config.ts Site identity, features, social links, and content settings
src/content.config.ts Content collection schemas
src/content/posts/   Blog posts
src/content/pages/   Static content pages
src/components/      Astro UI components
src/layouts/         Page and post layouts
src/pages/           Routes and generated endpoints
src/styles/          Global, theme, and typography styles
public/              Static assets
scripts/             Repository validation scripts
```

User-facing site settings live in `astro-paper.config.ts`. `src/config.ts`
resolves that configuration with defaults, and `src/types/config.ts` defines
its types.

## Local Development

Install dependencies:

```sh
pnpm install
```

Start the local dev server:

```sh
pnpm run dev
```

Validate post frontmatter:

```sh
pnpm run validate:posts
```

Run code-quality checks:

```sh
pnpm run lint
pnpm run format:check
```

Build the production site:

```sh
pnpm run build
```

Preview the production build:

```sh
pnpm run preview
```

The production build runs Astro checks, builds the site, generates Pagefind
indexes, copies the search bundle into `public/pagefind`, and validates the RSS
feed.

## Writing Content

New posts belong in `src/content/posts/` as `.md` or `.mdx` files. The
authoritative frontmatter schema is in `src/content.config.ts`.

Required post fields:

```yaml
---
title: Example title
description: A concise summary used in listings and metadata.
pubDate: 2026-07-27
tags:
  - Engineering
---
```

Optional fields are `author`, `modDate`, `slug`, `featured`, `draft`,
`series`, `ogImage`, `canonicalURL`, and `hideEditPost`. Use `pubDate` and
`modDate` exactly, with `YYYY-MM-DD` values.

Tags provide the site's topic taxonomy, so their spelling and casing should
remain consistent.

The first post in a series defines its shared metadata and reading order:

```yaml
series:
  id: personal-cloud
  title: Building a Personal Cloud
  description: Field notes from building a private platform.
  order: 1
```

Later posts need only `id` and `order`. A series is ongoing unless its
highest-order post sets `complete: true`. Builds reject missing first-post
metadata, duplicate order values, conflicting metadata, and invalid completion
markers.

Drafts are never published. Preview them locally with `pnpm dev:drafts`.
Future-dated non-draft posts are visible during
local development and excluded from production until their publication date.

## Routes and Features

- Posts use root-level URLs generated by `src/utils/getPostPaths.ts`.
- A post's `slug` overrides its filename-derived path and may contain nested
  segments.
- `/posts/` is the paginated listing; individual posts do not live beneath it.
- Series pages are derived from post frontmatter at `/series/[id]/`.
- `/tags/` is the Explore directory for both series and topics.
- Builds reject duplicate post URLs and reserved top-level routes.
- Pagefind powers static search.
- RSS is available at `/rss.xml`.
- Posts without a custom image receive a dynamically generated OG image.
- `public/default-og.jpg` is the site's static fallback OG image.
- Light and dark themes use IBM Plex Mono for UI and Source Serif 4 for prose.

## Deployment

Pull requests run frontmatter validation, linting, formatting checks, and the
production build. Pushes to `main` deploy to GitHub Pages.

The deployment workflow also runs daily at 00:15 UTC so future-dated posts can
be published without another commit.
